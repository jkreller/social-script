# Social Script Runner — Frontend

A React PWA that guides a user through a social script step by step. Scripts run **entirely on the client** — there is no backend on the request path (see [Python on the client](#python-on-the-client-pyodide)).

## Run locally

```bash
npm install
npm run dev
```

Open the printed URL in a browser (or on a phone on the same network using your machine's LAN IP). The `predev`/`prebuild` hooks copy the Pyodide runtime into `public/pyodide/` automatically — no backend needs to be running.

## Build

```bash
npm run build   # outputs to dist/
npm run preview # locally preview the production build
```

## Deploy to Vercel

The app is now **fully static** — no serverless functions, no backend env vars.

1. Push the repo to GitHub.
2. Import the project in Vercel. Set:
   - **Root directory**: `frontend`
   - **Framework preset**: Vite
3. Deploy. The PWA manifest and service worker are auto-generated by `vite-plugin-pwa` — the app is installable on iOS and Android from the browser, and the precached Pyodide runtime makes it work offline.

> The Pyodide runtime (~13 MB) is precached once per device install, not per visit. Pin the `pyodide` version so app redeploys don't re-fetch it.

## Install as a home screen app

- **iOS**: Open in Safari → Share → Add to Home Screen
- **Android**: Open in Chrome → three-dot menu → Add to Home Screen (or the install prompt)

Once installed, the app runs in `standalone` mode: fullscreen, no browser chrome.

## Architecture notes

- **`App.tsx`** — state machine `home → running → done`. Owns all session state: `answers[]`, `log[]`, `userName`. Persists the in-progress run to `localStorage` and restores it on load, so a run survives the PWA being killed (iOS does this aggressively when backgrounded) — replaying `answers[]` lands back on the same prompt.
- **`RunnerScreen`** — drives the `postStep` loop. One `AbortController` per request discards stale responses. `onAnswer(value, prompt)` bubbles to App.
- **`api.ts`** — `getScripts()`, `getExceptions()`, `postStep()`. Same signatures as the old HTTP client, but each call now runs in the Pyodide worker instead of hitting a server.
- **`engine/worker.ts`** — the Pyodide Web Worker that actually runs the Python (see below).
- **`engine/runtime.py`** — the three Python entry points (`step`, `list_scripts`, `list_exceptions`) called by the worker. Loaded once at startup; acts as the adapter between JS and the `social_script` package.
- **`types.ts`** — includes `LogEntry { timestamp, stepIndex, prompt, answer }` collected per answer and passed to `DoneScreen` for download.
- **`src/utils/downloadLog.ts`** — called by `DoneScreen`; generates a downloadable log from `{ userName, script, startTime, finishTime, log }`.

## Python on the client (Pyodide)

Scripts run in the browser via [Pyodide](https://pyodide.org) (CPython → WebAssembly) inside a Web Worker (`engine/worker.ts`), keeping the heavy interpreter off the UI thread.

Each step replays the whole script from the top, fast-forwarding through prior answers (`ReplayDriver`), so the script stays a pure function `(script, answers[]) → next prompt`. This makes runs resumable, undo trivial, and the engine shared across web/server/CLI — without needing `SharedArrayBuffer`/JSPI.

**How the Python gets there:** `engine/runtime.py` (the JS↔Python adapter) and the `social_script` package + scripts are inlined into the bundle as strings at build time via `import.meta.glob(..., { query: '?raw' })`. Pyodide itself (~13 MB) is copied into `public/pyodide/` by the `predev`/`prebuild` hook and precached by the service worker for offline use.

**Verifying offline:** `npm run build && npm run preview`, then DevTools → Network → Offline, reload the installed PWA and complete a full run.

## UI rules

The app is a calm field instrument. Keep it that way.

- `height: 100dvh`, `overflow: hidden` on root — no scroll, ever
- Light theme only: `--bg #f5f0e8`, `--fg #1a1a1a`, `--accent #b5600a` — accent used **only** for active states and headline labels
- Font: JetBrains Mono (Google Fonts, loaded in `index.html`)
- No UI libraries, no Tailwind — plain CSS modules only
- Touch-first — no hover dependencies
- No gradients, no decorations, transitions 150–250ms
- `onPointerDown` not `onClick`
- New UI must feel like it was always there — mirror existing patterns, never add on
- Simple and minimal in both UI and code — less is more, reuse what's there
